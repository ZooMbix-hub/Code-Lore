# Архитектура проекта

Проект построен по **feature-based** подходу, адаптированному под Next.js App Router:
главные оси — не горизонтальные слои, а вертикальные домены (`features/`) и граница
server ↔ client (RSC, серверные экшены). Вдохновлено структурой [relivator](https://github.com/reliverse/relivator),
без его «kitchen sink»-стека.

Раньше проект использовал FSD (Feature-Sliced Design) — от неё остались две лучшие идеи:
публичный API модуля через `index.ts` и запрет прямых импортов между модулями одного уровня.

## Структура

```
src/
├─ app/            # Только роутинг: page.tsx, layout.tsx, error/not-found/loading.
│                  # Страницы тонкие: получают данные → передают в компонент
├─ features/       # Вертикальные домены: запросы, типы и логика одного домена вместе.
│                  # Пример: features/docs — каталог документации
├─ ui/
│   ├─ primitives/ # Стилизованные обёртки над Base UI (@base-ui/react): Select, ...
│   ├─ components/ # Составные компоненты: Header, DocCard
│   └─ pages/      # Композиции страниц по роутам: pages/home, pages/docs, pages/section.
│                  # Presentational-компоненты с props + тесты рядом
├─ config/         # Конфиг приложения: routes.ts — карта роутов
├─ lib/            # Сквозные утилиты без знания о домене
└─ db/             # Drizzle: schema.ts, client.ts (ленивое подключение), seed.ts
```

## Правила

1. **`app/` — тонкий.** Данные достаём через `features/`, разметку отдаём в `ui/pages/`.
   Бизнес-логика в `app/` не живёт.

2. **`features/<домен>/` — вертикальный слайс.** Всё, что относится к домену, лежит вместе:
   запросы (`queries.ts`), серверные экшены (`actions.ts` с `'use server'`), типы, логика.
   Наружу модуль смотрит через `index.ts` — импортировать внутренности (`features/docs/queries`)
   снаружи нельзя.

3. **Слайсы друг друга не импортируют.** Нужно что-то общее — выносим в `lib/` (утилиты),
   `config/` (конфиг приложения), `db/` (схема) или `ui/` (компоненты).

4. **`ui/` трёхуровневый.** `primitives` не знает о домене; `components` — знает и собирает
   из примитивов; `pages/<роут>/` — композиция целой страницы (`index.tsx`): получает данные
   через props от тонкого `page.tsx`, из доменных компонентов (`DocCard`) и примитивов.
   Композиции — presentational-компоненты, поэтому легко тестируются без БД.

5. **`db/` — единственное место с Drizzle.** Схема, клиент и сид; `drizzle.config.ts` в корне
   ссылается на `src/db/schema.ts`. Клиент — ленивый Proxy: импорт `db` не открывает соединение
   до первого запроса (это позволяет тестам и сборке работать без поднятой БД).

6. **Граница server/client живёт внутри модулей.** По умолчанию всё — Server Components;
   `'use client'` вешается точечно на интерактивные листья (формы, редакторы).

## Что класть куда: шпаргалка

| Хотите добавить…                        | Куда                                           |
| --------------------------------------- | ---------------------------------------------- |
| Новый маршрут                           | `app/<роут>/page.tsx`                          |
| Новый домен (заказы, поиск, статьи)     | `features/<домен>/` + `index.ts`               |
| Запрос/мутацию для существующего домена | `features/<домен>/queries.ts` или `actions.ts` |
| Таблицу в БД                            | `db/schema.ts` + миграция                      |
| Кнопку/инпут общего назначения          | `ui/primitives/`                               |
| Компонент из доменных сущностей         | `ui/components/`                               |
| Композицию/экран для нового роута       | `ui/pages/<роут>/index.tsx`                    |
| Утилиту без знания о домене (`slugify`) | `lib/`                                         |
| Конфиг приложения (роуты, константы)    | `config/`                                      |
| Внешнюю интеграцию (платежи, почта)     | `lib/integrations/<сервис>/`                   |

## Контроль

- `oxlint` + `oxfmt` (pre-commit через husky + lint-staged).
- Тесты колоцируются с кодом (`*.test.tsx` рядом с компонентом) — vitest + Testing Library.
- `drizzle/` исключён из форматирования (`.oxfmtrc.json`) — снапшоты генерирует drizzle-kit.
