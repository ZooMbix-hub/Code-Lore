# Архитектура проекта

Проект построен на методологии [Feature-Sliced Design](https://feature-sliced.design/ru/) (v2), адаптированной под Next.js App Router.

Единственное алиас-правило из канона, которое здесь изменено: слой `pages` заменён на слой `views`, потому что файловый роутинг в Next.js занимает каталог `app/` — он и выполняет роль верхнего слоя `app` из FSD.

## Слои

```
src/
├─ app/        # Роутинг Next.js: layouts, страницы-обёртки, error/not-found/loading, globals.css
├─ views/      # Экраны: составные страницы из widgets (замена канонического слоя pages)
├─ widgets/    # Крупные самостоятельные блоки интерфейса: DocsLayout, Sidebar, Header
├─ features/   # Пользовательские сценарии: поиск, переключение темы, версия документации
├─ entities/   # Доменные модели: сущность «страница документации», «раздел навигации»
└─ shared/     # Фундамент, не знающий о предметной области: ui-кит, lib, config, types
```

Слои перечислены от верхнего к нижнему. Чем выше слой — тем больше он знает о продукте, тем меньше причин его переиспользовать в других проектах.

## Правило импортов

**Импортировать можно только строго вниз** по списку слоёв:

```
app → views → widgets → features → entities → shared
```

| Слой       | Может импортировать из                               |
| ---------- | ---------------------------------------------------- |
| `app`      | `views`, `widgets`, `features`, `entities`, `shared` |
| `views`    | `widgets`, `features`, `entities`, `shared`          |
| `widgets`  | `features`, `entities`, `shared`                     |
| `features` | `entities`, `shared`                                 |
| `entities` | `shared`                                             |
| `shared`   | только внешние пакеты                                |

Обратные импорты (например, `shared` → `entities`) запрещены.

## Публичный API слайса

Каждый слайс (каталог внутри слоя: `views/home`, `features/search`, `entities/doc-page`…) общается с внешним миром только через `index.ts`. Всё, что не экспортировано из `index.ts`, считается деталью реализации:

```ts
// ❌ импорт внутрь слайса
import { HomePage } from '@/views/home/ui/home-page';

// ✅ импорт из публичного API
import { HomePage } from '@/views/home';
```

## Кросс-слайсовые импорты

Внутри одного слоя слайсы не импорируют друг друга: `features/search` не может импортировать `features/theme`. Если двум слайсам нужна общая логика — вынесите её на слой ниже (в `entities` или `shared`).

## Структура слайса

Слайс состоит из сегментов. Создавайте только нужные, а не все сразу:

```
views/home/
├─ ui/           # Компоненты: home-page.tsx + home-page.test.tsx рядом
├─ model/        # Состояние: store, hooks (если есть)
├─ api/          # Запросы к серверу (если есть)
├─ lib/          # Локальные утилиты слайса (если есть)
└─ index.ts      # Публичный API слайса
```

Тесты колоцируются с кодом: `home-page.test.tsx` лежит рядом с `home-page.tsx`. Общих каталогов `__tests__` нет.

## Слой app

`app/` — единственное место, знающее о Next.js-роутинге:

- `page.tsx` — тонкая обёртка: получает параметры роута, достаёт данные, передаёт во вьюху;
- `layout.tsx` — шрифты, глобальные стили, провайдеры;
- `error.tsx`, `not-found.tsx`, `loading.tsx` — роутинговые спец-файлы.

Бизнес-логика и разметка экранов в `app/` не живут — только композиция.

## Механический контроль

В `.oxlintrc.json` настроен override: импорт `@/app/*` из любого файла вне `src/app/**` падает с ошибкой — это ловит самое частое нарушение направления импортов.

Остальные правила (направление между слоями, кросс-слайсовые импорты, публичные API) пока контролируются ревью. Когда появятся реальные слайсы во всех слоях — имеет смысл добавить [steiger](https://github.com/instant-labs/steiger) или `eslint-plugin-boundaries`.

## Что класть куда: шпаргалка

| Хотите добавить…                              | Куда                                 |
| --------------------------------------------- | ------------------------------------ |
| Кнопку/инпут/модалку общего назначения        | `shared/ui`                          |
| Утилиту без знания о домене (`cn`, форматтер) | `shared/lib`                         |
| Конфиг сайта (название, ссылки, соцсети)      | `shared/config`                      |
| Тип доменной области                          | `entities/<сущность>`                |
| Поиск по документации                         | `features/search`                    |
| Сайдбар + шапку + содержание страницы         | `widgets/docs-layout`                |
| Целый экран «Страница документации»           | `views/docs`                         |
| Новый маршрут `/docs/[...slug]`               | `app/(docs)/docs/[...slug]/page.tsx` |
